  <action>
  Open Makefile and locate the `sign` target (lines 106-112). The current content is:

    sign:
    [TAB]find "$(PYTHON_RUNTIME)/venv" \( -name "*.dylib" -o -name "*.so" \) \
    [TAB]    | xargs -I{} codesign --force --sign - --options runtime "{}"
    [TAB]codesign --force --sign - --options runtime \
    [TAB]    --entitlements "$(ENTITLEMENTS)" \
    [TAB]    "$(APP)"
    [TAB]@echo "sign: ad-hoc code signing complete"

  Insert a NEW recipe line between the `.so`/`.dylib` codesign step and the outer `.app` codesign step. The inserted line signs all executable files in `venv/bin/`:

    [TAB]find "$(PYTHON_RUNTIME)/venv/bin" -type f -perm +111 \
    [TAB]    | xargs -I{} codesign --force --sign - --options runtime "{}"

  After the edit the full `sign` target must read:

    sign:
    [TAB]find "$(PYTHON_RUNTIME)/venv" \( -name "*.dylib" -o -name "*.so" \) \
    [TAB]    | xargs -I{} codesign --force --sign - --options runtime "{}"
    [TAB]find "$(PYTHON_RUNTIME)/venv/bin" -type f -perm +111 \
    [TAB]    | xargs -I{} codesign --force --sign - --options runtime "{}"
    [TAB]codesign --force --sign - --options runtime \
    [TAB]    --entitlements "$(ENTITLEMENTS)" \
    [TAB]    "$(APP)"
    [TAB]@echo "sign: ad-hoc code signing complete"

  Critical: all recipe lines use hard-tab indentation (not spaces). `$(PYTHON_RUNTIME)` is already defined in the Makefile as `$(BUNDLE_RESOURCES)/python-runtime`. Do not redefine it. The `--options runtime` flag is required for Gatekeeper compatibility — include it exactly as shown. `-perm +111` selects any file with any executable bit set (owner, group, or world), which matches the macOS `find` BSD dialect (GNU `find` uses `-perm /111`; this Makefile targets macOS so BSD form is correct).
  </action>
