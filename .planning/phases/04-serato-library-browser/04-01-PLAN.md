<objective>
Build the Python backbone for the Serato Library Browser: a new `library.py` module that parses the `.crate` hierarchy, reads per-track beatgrid source, and exposes two new IPC commands; plus the coordinated `pack_beatgrid()`/`decode_beatgrid()` version-byte change (D-07) that makes this tool's beatgrids self-identifying.

This is the first vertical slice: after this plan, the Python worker process answers `{"cmd":"list_crates"}` and `{"cmd":"list_tracks","crate":...}` over stdin/stdout JSON-Lines, exactly the contract the Swift layer (Plan 02) consumes. All test gates for LIB-01, LIB-02, LIB-03 live here.

Purpose: Keep all binary `.crate` and GEOB parsing in Python (D-04, D-05) where serato-tools + mutagen already exist — no Swift binary parsing.
Output: `python/library.py`, extended `python/analyze.py` worker loop, version-byte change, `requirements.txt` entry, and `python/tests/test_library.py` + new `test_geob.py` cases.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-PT | Tampering | list_tracks(crate_path) | mitigate | Validate crate_path resolves inside the Subcrates dir (Path.resolve() startswith subcrates_dir) before opening; emit error otherwise |
| T-04-DOS | Denial of Service | Crate() on malformed .crate | mitigate | serato-tools raises on invalid files; wrap in try/except → emit_error, worker stays alive (WR-03 pattern) |
| T-04-ID | Information Disclosure | read_beatgrid_source over arbitrary path | accept | Library lists only paths returned by Serato's own crate files; no path traversal beyond user's music library |
| T-04-SC | Tampering | serato-tools dependency | mitigate | serato-tools 2.4.0 pre-existing in venv, audited in RESEARCH Package Legitimacy Audit; pinning >=2.4.0 only |
</threat_model>
